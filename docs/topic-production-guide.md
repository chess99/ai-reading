# 主题文章与页面生产指南

主题正文面向第一次进入页面的读者。内容应帮助选书、理解差异与开始阅读；改版理由、内部讨论、任务分工和审批状态属于维护资料，不进入正文或界面。

## 从策展到文章

1. 确定读者问题、范围、受众和适合的阅读方式。
2. 独立选择书目，核对作品身份、内容贡献、难度与适用性。
3. 匹配馆藏：有可靠对应才设置站内链接，否则保留待补解读状态。
4. 写清起读点与不同读法，再组织正文；不按统一角色顺序给书单补过渡。
5. 核查页面、书目、链接、相关主题与历史地址；通过验证后提交本次变更。

具体策展判断见 `topic-curation-policy.md`。

## 内容格式

```yaml
---
slug: topic-slug
title: 中文主题标题
description: 具体说明读者可以了解什么。
tags: [标签]
domain: 科学
domains: [科学, 思维]
mode: comparison
entry: 说明适合的读者处境或起读方式。
related: [related-topic-slug]
date: 'YYYY-MM-DD'
books:
  - title: 书名
    author: 作者
    originalTitle: 原作标题
    reading: start
    role: 具体内容角色
    reason: 说明这本书对当前主题的贡献。
    status: planned
---
```

- `mode`：`path` 按问题选读、`comparison` 比较阅读、`collection` 作品与经验。
- `reading`：`start` 起读、`next` 继续、`compare` 对照、`optional` 按需、`reference` 查阅深入。
- `originalTitle`：可选，尤其用于待入库译作的身份识别。
- 已入库条目使用 `status: in_library`，附真实 `slug` 和 `path`，标题与作者和馆藏一致。
- `domain` 是主要归属，等于 `domains` 第一项；其他领域提供同等可达的浏览入口。
- `related` 只列实际存在且与读者问题有关的主题，不要求对称链接。

正文以与标题相同的一级标题开始。篇幅、小节与形式服从内容，可以用短文、问题比较或作品细读；不强制统一章数和结束句式。

## 写作判断

开头应让读者知道将进入什么问题。短描述不要复述标题并堆叠“框架、实践、系统”等通用词；推荐理由要说清具体贡献。

正文负责解释书之间的关系、适用条件与值得留意的分歧，不必把每张卡片重新扩写一遍。“建议读法”应提供选择、跳读、比较或与实际任务配合的方式，避免再次罗列全书单。

不要写“本轮”“此前删除”“按计划”“保持几本”“用户要求”“已批准”等生产过程。只有历史地址迁移页需要帮助使用旧链接的读者找到正确目的地，也应直接提供去向而非讲述内部争论。

不要为显得自然虚构个人阅读经历。避免反复使用“不是……而是……”“放在最后是为了……”与统一的道理式结尾。必要的概念区分应保留，但每一次都应带来信息。

## 页面

- 开头显示起读书与适用场景，不让读者滚完整篇才找到入口。
- 正文中的荐读书名链接到已入库解读，或本页的待补书说明。
- 完整书单明确读法与可读状态，不用连续序号暗示所有书必须依次完成。
- 相关主题支持继续探索，不规定先修关系。
- 新增或变更旧地址时维护 `.nextjs-site/data/topic-legacy-routes.json`，直接指向现存主题；拆分提供多个明确目的地。

## 验证

自动检查身份字段、状态、路径、起读点、关系引用和迁移路由；编辑检查内容身份、证据与表达。测试不应冻结某次策展的父子关系或固定书数。

涉及页面时完成类型检查、相关测试、静态构建，并检查桌面与小屏阅读、搜索和跳转。已有无关问题应单独记录，不能通过放宽测试隐藏。
