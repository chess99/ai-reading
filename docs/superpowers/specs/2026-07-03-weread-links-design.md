# 微信读书原书链接设计

## 背景

书籍详情页目前只展示本站整理的书籍提炼。读者如果想继续阅读原书，需要自行搜索。新增微信读书链接后，读者可以从书籍页直接跳转到微信读书查看原书。

这个能力应作为外部平台增强层，而不是书籍内容本体的一部分。链接维护应尽量减少对 `books/` Markdown 文件的侵入，避免批量补充链接时产生几百个书籍文件 diff。

## 用户体验

入口放在书籍详情页标题区，位于作者下方。

- 有微信读书链接时，显示一个主动作按钮：`微信读书看原书 ↗`
- 没有链接时，不显示按钮，也不保留占位
- 按钮打开新标签页，并使用 `rel="noopener noreferrer"`
- 不展示额外说明文案，例如“跳转到正版阅读平台”

这个位置发现性强，也不会打断正文阅读。按钮属于当前书籍的操作，而不是正文内容的一部分。

## 数据模型

新增独立链接清单文件：

```text
.nextjs-site/data/weread-links.json
```

结构使用 slug 到状态对象的映射：

```json
{
  "cong-ling-dao-yi": {
    "status": "found",
    "url": "https://weread.qq.com/web/bookDetail/...",
    "checkedAt": "2026-07-03"
  },
  "mou-ben-shu": {
    "status": "not_found",
    "checkedAt": "2026-07-03",
    "note": "按书名和作者未找到可靠匹配"
  }
}
```

状态含义：

- 没有 key：还没有查过微信读书
- `status: "found"`：已找到并人工核验微信读书书籍页链接，页面展示按钮
- `status: "not_found"`：已人工查过但没有可靠且当前可读的匹配，页面不展示按钮

`checkedAt` 不是“脚本搜索日期”，而是该映射最近一次完成**书目身份、当前可读性和合理版本候选**人工复核的日期。

选择独立文件的原因：

- 微信读书链接是外部平台增强数据，不属于书籍提炼正文
- 批量补链接时 diff 集中，便于审查和回滚
- 能像插件一样安装或拆卸，不污染 `books/` 内容文件
- slug 是站内书籍的稳定标识，适合做清单 key

## 构建期读取

链接清单只在构建期读取，不作为前端公开 data asset。

实现方式：

- 新增服务端工具模块读取 `.nextjs-site/data/weread-links.json`
- 书籍详情页按当前 `book.slug` 查询微信读书链接
- 只把当前书的 `wereadUrl` 字符串或 `null` 传给客户端组件
- 前端页面不会下载整份链接清单，也不会额外请求 data 文件

这样可以保持页面产物轻量，并避免暴露无关书籍的完整外链表。

## 校验与维护

基础结构校验测试：

- `weread-links.json` 必须是 JSON object
- 每个 key 必须对应现有书籍 slug
- 每个 entry 必须使用 `found` 或 `not_found` 状态
- `found` entry 必须包含来自 `weread.qq.com` 的书籍详情 URL
- `not_found` entry 不应包含 URL
- 每个 entry 必须包含 `checkedAt: YYYY-MM-DD`
- 同一个 URL 不应重复绑定到多本书

### Agent 人工复核边界

微信读书的搜索结果、标题相似度和作者匹配只能生成候选，不能直接成为最终映射。维护脚本必须保持 review-only，不得根据分数自动写入 `found`、`not_found` 或替换 URL。

agent 对每条最终映射至少检查：

1. 候选是否确实是同一本原著，书名和作者是否一致；
2. 详情页当前是否仍有正常的“加入书架/开始阅读”等阅读入口，而不是只剩历史书目页；
3. 是否还有同一本书的其他正式版本，尤其是旧版不可读但新版仍在架的情况；
4. 是否误命中同名异书、解读/导读、节选、套装/合集或作者不符的结果。

同一本书有多个版本时，当前可正常阅读的正式版本优先于已下架或不可读版本；多个版本都可读时，通常优先较新的正式中文版，但如果本站提炼明确基于特定版本，应先比较内容差异而不是机械追新。

只有在人工搜索书名、作者及必要的译名/版本变体后仍没有可靠且当前可读的候选，才记录 `not_found`。网络错误、页面抓取失败、反爬或工具失败都不能被当成 `not_found`。

`.nextjs-site/scripts/fetch-weread-links.mjs` 可以用于搜索和排序候选，但其输出只是 agent 的工作材料。最终 JSON 修改必须发生在 agent 完成人工复核之后。

## 变更范围

预计修改：

- 新增 `.nextjs-site/data/weread-links.json`
- 新增或扩展 `.nextjs-site/lib/` 中的构建期链接读取模块
- 修改 `.nextjs-site/app/books/[slug]/page.tsx`，把当前书链接传给客户端
- 修改 `.nextjs-site/app/books/[slug]/page-client.tsx`，渲染标题区按钮
- 增加测试覆盖链接清单校验与按钮渲染约束

不修改：

- 不批量改 `books/` Markdown frontmatter
- 不在运行时抓取微信读书
- 不把链接清单放入 `public/`
- 不改变现有书籍 slug、目录规范或正文结构

## 验收标准

- 有链接的书籍页标题区显示 `微信读书看原书 ↗`
- 无链接的书籍页不显示任何微信读书入口
- 构建产物不需要额外加载整份链接清单
- 链接清单中非法 slug、非法状态、非法域名、缺失检查日期或重复 URL 会被测试发现
- 候选搜索脚本不会直接修改链接清单，最终映射经过 agent 人工复核
- 现有书籍详情页布局在桌面和移动端保持稳定
