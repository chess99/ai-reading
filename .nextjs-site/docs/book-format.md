# 书籍内容规范

本文档说明如何向 `books/` 目录添加或维护书籍解读，包括目录位置、frontmatter 字段、正文组织与校验要求。整体命名和入库纪律见仓库根目录的 [AGENTS.md](../../AGENTS.md)。

## 文件命名与目录

文件路径必须符合固定两级书架结构：

```text
books/<一级分类>/<二级分类>/<作者>-<书名>.md
```

示例：

- `books/职业组织/管理通论/彼得·德鲁克-卓有成效的管理者.md`
- `books/金钱投资/价值投资/本杰明·格雷厄姆-聪明的投资者.md`
- `books/商业产品/商业战略/彼得·蒂尔,布莱克·马斯特斯-从零到一.md`

说明：

- 一级与二级分类以 `docs/superpowers/plans/2026-06-14-book-directory-taxonomy.md` 的目录树为准，禁止将书直接放在一级分类根目录或自建三级目录。
- 文件名中的书名使用**中文通用译名**，不加版本号（例如用 `笑傲股市`，不用 `笑傲股市（原书第4版·典藏版）`；品牌缩写如 `ACSM高级运动生理学` 可保留英文）。
- 多作者用英文逗号分隔：`作者A,作者B`。

## Frontmatter 规范

文件开头使用标准 YAML frontmatter：

```yaml
---
slug: <书名拼音，不含作者名和版本号>
title: <网站最终展示标题，可含副标题>
author: <作者完整中文译名，或原作者名>
tags: [标签1, 标签2]
date: 'YYYY-MM-DD'
---
```

字段要求：

- `slug`：由中文书名转写的小写拼音连字符（或英文原名小写连字符），**不含作者名和版本号**，仅含字母、数字与 `-`；同类同名异书时再加作者前缀区分。已有书籍已公开的 `slug` 保持稳定。
- `tags`：必须使用行内数组 `[标签1, 标签2]`，不用多行 YAML 列表。
- `date`：使用单引号包裹的 `YYYY-MM-DD` 日期字符串，对应入库或实质重写的日期。

## 正文结构与写作要求

### 1. 一级标题

紧跟在 frontmatter 之后的第一行必须是正文一级标题，使用中文主书名，**不加副标题或“综合提炼”等后缀**：

```markdown
# 卓有成效的管理者
```

### 2. 按作品体裁组织正文

正文不强求千篇一律的“核心论点 / 章节精华 / 金句摘录 / 行动清单”八股模板，具体小节结构服从原书内容：

- **知识、商业、社科与科普作品**：保留作者的问题、论证逻辑、关键方法、实证案例与方法成立条件。把适用条件自然融进机制叙述里，不把导读或每段结尾写成合规免责声明。
- **小说、戏剧与叙事作品**：写成连贯完整的剧情与人物经历讲述，讲清人物想做什么、冲突怎样推进、付出了什么代价、结局如何，不套“人物分析 / 主题提炼 / 阅读指南”评论框架，也不借续集或影视改编补剧情。
- **诗歌、书信与非叙事散文**：依真实篇章、情境与表达脉络展开，不虚构统一剧情，也不硬拆成行动清单。

### 3. 语言清晰克制

面向真实读者写作，写清人物、作者或研究者具体做了什么，以及因果、条件与代价：

- 不使用“不是/不只是 X，而是 Y”“不在 X，而在 Y”作为空泛反衬模板，也不将句子倒装成“是 Y，X 不在其中/并非 X”式多余尾巴。
- 不在段尾追加“这说明/这意味着……”或“书单不构成……建议”类说教与免责尾巴，也不用“值得注意的是 / 核心是 / 首先其次 / 综上所述”等过渡套话铺垫。
- 有序或无序列表中的加粗引导词在同组列表内保持格式一致。

## 微信读书链接与自动化校验

- **微信读书映射**：所有书稿的站外阅读入口统一维护在 `.nextjs-site/data/weread-links.json`，不写入 Markdown frontmatter。每次新增书籍、调整 `slug` 或实质修改书名/作者时，须同步核验更新并标记 `found` 或 `not_found`。
- **slug 检查 hook**：仓库通过 husky 在 commit 阶段自动检查新增书籍的 `slug` 是否缺失或冲突；也可在根目录手动执行 `npm run slugify`。
- **提交前测试**：在 `.nextjs-site/` 下运行：

```bash
node --test tests/book-taxonomy.test.mjs tests/weread-links.test.mjs tests/feeds.test.mjs tests/book-related-topics.test.mjs
```
