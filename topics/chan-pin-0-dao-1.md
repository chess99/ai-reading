# 产品从 0 到 1

产品从 0 到 1 难，不是因为团队不会做功能，而是因为团队很容易把“做出来”误当成“被验证”。真正的不确定性在更前面：这个问题是否真实，用户是否足够痛，现有替代方案为什么不够，产品能否形成独特价值，团队能否持续交付并找到增长路径。

这条路径保留既有 slug，但按计划重建为合并后的 0 到 1 路径：先判断独特命题，再用验证学习和客户开发确认需求，随后进入产品发现、需求组织、交付系统、创业管理和增长实验。机会验证和产品发现先作为这条路径中的阶段，不单独拆页。

## 入口：先判断是否值得做

《从零到一》放在第一本，因为它要求团队回答一个更早的问题：你看见了什么别人没有看见的重要真相？如果产品只是已有方案的轻微优化，0 到 1 的难度会被低估。

《精益创业》把这种战略判断拉回实验。愿景和计划都只是未验证假设，团队需要用最小成本验证最关键的不确定性。它提醒读者，MVP 的目的不是快速上线，而是快速学习。

## 框架：走出办公室确认需求

《四步创业法》提供客户开发的阶段框架，说明创业早期是在寻找可重复、可扩展的商业模式，而不是执行一份已经正确的计划。《客户开发入门》把这件事落到访谈现场，帮助团队理解客户任务、约束、购买动机和替代方案。

《妈妈测试》继续校准访谈质量。用户的鼓励、想象和礼貌很容易误导团队。好的问题要围绕过去行为、真实成本和具体场景，而不是问“你会不会用”。

## 系统：发现、组织和交付

《启示录》把客户理解转化为现代产品发现：产品经理、设计、工程和业务如何共同判断机会、定义价值和减少风险。《用户故事地图》帮助团队把用户任务、旅程、版本切分和优先级组织起来，避免需求列表变成失控的待办堆。

《产品开发流程原理》说明交付本身也是系统问题。队列过长、批量过大、反馈过慢和在制品过多，都会让产品开发变得迟缓而昂贵。0 到 1 阶段尤其需要短反馈周期，因为错误越晚发现，代价越高。

## 实践：公司压力和增长实验

《创业维艰》补上创业管理的现实。产品验证不是在干净环境里发生的，团队会遇到现金、人员、信任、裁撤、转向和压力决策。读它是为了理解产品从无到有背后的组织代价。

《增长黑客》放在最后，因为增长不应是上线后的补救。激活、留存、推荐和收入都需要进入实验系统。好的增长来自产品价值被更快体验、更自然复用，而不是一次性的推广动作。

## 建议读法

先读《从零到一》和《精益创业》，建立“独特命题 + 验证学习”的张力；再读《四步创业法》《客户开发入门》《妈妈测试》，把需求验证落到真实用户；随后读《启示录》《用户故事地图》《产品开发流程原理》，建立产品发现和交付系统；最后读《创业维艰》和《增长黑客》，理解创业压力与增长实验。

阅读时可以把每本书压缩成一个问题：我们有什么独特判断？最关键假设是什么？谁真的痛？用户现在如何替代？访谈有没有被礼貌误导？产品发现是否在降低风险？交付反馈够不够快？增长来自真实价值还是外部刺激？
